# 阶段9-个人内容管理系统技术设计方案.md

# 一、系统升级目标

## 1.1 当前系统状态

当前网站：

React + Vite 前端应用

数据来源：

静态数据文件（data/\*.ts）

特点：

-   展示稳定
-   页面完整
-   项目结构已经确定

但是存在限制：

-   修改内容需要修改代码
-   无法在线管理
-   无法快速发布新项目和日志

------------------------------------------------------------------------

## 1.2 阶段9升级目标

将网站升级为：

> 一个支持后台管理、数据库存储、内容持续更新的个人开发者数字资产管理系统。

升级后：

管理员可以通过后台：

-   修改个人资料
-   管理项目
-   管理实验室内容
-   发布成长日志
-   修改联系方式

无需修改代码即可更新网站内容。

------------------------------------------------------------------------

# 二、整体系统架构设计

## 2.1 系统结构

    用户

    ↓

    React 前台网站

    ↓

    Supabase Client

    ↓

    Supabase Database

    ↓

    管理员后台

    ↓

    Supabase Auth

------------------------------------------------------------------------

## 2.2 模块组成

系统分为：

## 前台展示系统

负责：

-   首页
-   关于我
-   项目展示
-   实验室
-   成长日志
-   联系页面

## 后台管理系统

负责：

-   登录认证
-   内容编辑
-   数据管理

## 数据服务层

负责：

-   数据请求
-   CRUD操作
-   数据转换

------------------------------------------------------------------------

# 三、技术选型

## 3.1 前端技术

保持现有：

-   React
-   Vite
-   TypeScript
-   React Router

样式：

-   Tailwind CSS
-   shadcn/ui（后台组件）

------------------------------------------------------------------------

## 3.2 数据库方案

采用：

Supabase

原因：

-   PostgreSQL数据库
-   自带认证系统
-   提供API
-   支持文件存储
-   适合个人项目

------------------------------------------------------------------------

## 3.3 数据状态管理

推荐：

React Query

负责：

-   数据缓存
-   自动刷新
-   请求状态管理

------------------------------------------------------------------------

# 九、服务层设计

    services/

    ├── supabase.ts

    ├── projects.service.ts

    ├── logs.service.ts

    └── labs.service.ts

# 十二、安全设计

-   使用环境变量
-   不提交密钥

-   验证用户身份
