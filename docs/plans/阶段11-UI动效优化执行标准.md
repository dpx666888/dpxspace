## 五、暂停条件（必须暂停并等待决定）

出现以下任一情况，立即停止当前批次，不做进一步修改：

1. 需要新增依赖、修改技术栈、路由架构或数据库。
2. 实际需要修改的代码文件超出清单，或单批 > 5 个。
3. 需要改变已确认的视觉方案、布局矩阵或交互语义。
4. 验收指标不达标，且修复需要架构性改动或超出本批范围。
5. 遇到数据边界（n = 0/1/2/≥3 之外的异常状态）、空数据、加载失败等未覆盖场景。
6. 浏览器兼容性或控制台报错无法在 10 分钟内定位。
7. 发现既有 bug，且修复它会扩大本批范围。
8. 需要决定文案、排序、内容取舍。
9. Git 冲突、工作区出现非预期改动、或需要回滚已推送提交。
10. 任何与 `开发规则.md` 或本文件冲突的操作。

暂停时必须输出：

```

影响面：
我的建议：
```

## 六、每批执行 SOP

1. **前置检查**：`git status` 只包含本批预期文件；读取本文件对应章节。
2. **实现**：严格按文件清单改动。
3. **类型检查**：`npx tsc --noEmit`。
4. **构建**：`npm run build`，记录 raw / gzip 体积。
5. **预览**：`npm run preview`，使用 Playwright / Lighthouse 验收（临时工具，不写入依赖）。
6. **自检**：逐条核对本批验收标准，全部通过才进入提交。
7. **代码提交**：`type: description`，只包含本批代码文件。
8. **开发记录**：`docs/development-log/0XX-<批次名>.md`，按 `开发规则.md` 格式，并增加 `## 验收结果` 一节。
9. **文档提交**：`docs: 第0XX次开发记录-<批次名>`。
10. **汇报**：按第九章格式输出；A 批后暂停等待确认。

验收未通过时，不得提交、不得进入下一批；修复后重新从第 3 步执行。

## 十二、回滚手册

- 单批代码回滚：`git revert <代码提交 hash>`，生成新提交，不改写历史。
- 开发记录单独回滚：`git revert <docs 提交 hash>`。
- B2b 两个提交可分别回滚。
- 回滚后必须重新执行 `npx tsc --noEmit` 与 `npm run build`。
- 禁止 `git reset --hard`、`git push --force`。
