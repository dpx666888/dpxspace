## 三、问题详情

### SEC-01（P0）草稿/归档项目对公网可读

**问题描述**
项目列表查询与详情查询均未过滤 `status`，同时数据库匿名读策略为无条件放行。`draft` / `archived` 项目会出现在 `/projects`、首页以及站内详情页，也可通过 URL 直接访问。

**证据**
- `src/services/projects.service.ts:12`：`getProjects()` 仅 `select('*')`，无 `status` 过滤。
- `src/services/projects.service.ts:30`：`getProjectBySlug()` 同样无 `status` 过滤。
- `supabase/migrations/001_initial_schema.sql`：`create policy "Allow public read projects" on projects for select using (true);`

**影响**
后台“草稿”状态形同虚设，未完成内容可能被搜索引擎收录或访客直接访问，属于内容层面的信息泄露。

**修复建议**
1. 公开查询增加 `.eq('status', 'published')`（列表与详情一致）。
2. RLS 改为匿名仅可读已发布：`using (status = 'published')`；认证用户保留全量读取。
3. 后台与前台使用不同的 query key（如 `['projects','public']` / `['projects','admin']`），避免缓存互相污染。

**验证方式**
匿名浏览器访问草稿项目详情 URL 应返回 404/未找到；前台列表不出现草稿；后台仍可见草稿。

### SEC-02（P0）任意已注册用户拥有全站写权限

**问题描述**
所有写策略均只判断 `auth.uid() IS NOT NULL`，Storage 上传/删除策略也只判断 `authenticated` 角色。如果 Supabase Auth 允许公开注册，任何注册用户都能修改站点内容、上传或删除图片。

**证据**
- `supabase/migrations/002_fix_rls_policies.sql`：各表 `FOR ALL USING (auth.uid() IS NOT NULL)`。
- `supabase/migrations/010_storage_fix.sql`：`FOR INSERT TO authenticated WITH CHECK (bucket_id = 'gallery')`，删除策略同理。
- `src/admin/hooks/useAuth.tsx:50`：`isAdmin` 等价于 `!!user`，未校验角色。

**影响**
内容被未授权用户篡改的风险；属于最高优先级安全问题。

**修复建议**
1. 在 Supabase Auth 设置中关闭公开注册（仅邀请/手动创建账号）。
2. RLS 收敛到管理员 UID 或 `profiles.role`，例如 `auth.uid() = '<管理员 UID>'`。
3. Storage 的 INSERT/DELETE 策略同步收敛。
4. 前端 `isAdmin` 增加角色判断（作为体验层，最终以 RLS 为准）。

**验证方式**
用非管理员账号登录后调用写接口应被拒绝；匿名用户无法上传/删除。

### BUG-01（P1）About 页图标映射不完整可导致崩溃

**问题描述**
前台 About 页维护了一份仅包含 8 个图标的局部映射，但后台 IconPicker 可选 40+ 个图标。后台选择映射外的图标后，前台渲染 `<Icon>` 时组件为 `undefined`，React 会抛出 “Element type is invalid”，且项目没有 ErrorBoundary 兜底，整页白屏。

**证据**
- `src/pages/About.tsx:17`：局部 `iconMap` 仅 8 项。
- `src/pages/About.tsx:85`、`:112`、`:145`：直接使用 `iconMap[cat.icon]`，无兜底。
- `src/admin/components/IconPicker.tsx:12`：可选图标约 41 个。
- `src/lib/icons.ts:19`：项目已有带兜底的 `getIcon()`，但 About 页未使用。
- `src/pages/Contact.tsx:13`：重复维护了一份完整映射（有 `|| Link` 兜底）。

**影响**
后台一次图标选择即可让关于页崩溃；属于高概率、易触发的功能缺陷。

**修复建议**
统一使用 `src/lib/icons.ts` 的 `getIcon()`；删除 About/Contact 的局部映射；补充全局 ErrorBoundary。

**验证方式**
后台将某个分类/实践/证书图标改为 `Rocket`，前台 About 页应正常显示且不崩溃。

### BUG-02（P1）编辑项目后详情页缓存不失效

**问题描述**
项目更新成功后失效的是数字 id 维度的 key，而详情页使用的是 slug 维度 key，导致详情页继续保持旧缓存（默认 staleTime 5 分钟）。

**证据**
- `src/admin/hooks/useProjectMutations.ts:21`：`qc.invalidateQueries({ queryKey: ['project', String(vars.id)] })`。
- `src/hooks/useProjects.ts:16`：详情 key 为 `['project', slug]`。

**影响**
后台修改项目后，前台详情页在缓存过期前展示旧内容，容易被误判为保存失败。

**修复建议**
失效 `['project']` 前缀；如需要精确失效，可同时失效 `['project', slug]`（需把 slug 传入 mutation 变量）。

**验证方式**
修改项目标题并保存，立即打开对应 `/projects/:slug`，应显示新内容。

### BUG-03（P1，需实测确认）拖拽排序 upsert 可能违反 NOT NULL 约束

**问题描述**
项目/日志/实验室的排序保存只提交 `{ id, sort_order }` 并调用 `upsert`。PostgREST 的 upsert 语义是 `INSERT ... ON CONFLICT DO UPDATE`，未提供的 NOT NULL 且无默认值的列会先被置为 NULL，从而在插入阶段报错。

**证据**
- `src/services/projects.service.ts:99`：`reorderProjects` 只传 `id / sort_order`。
- `src/services/logs.service.ts:79`：`reorderLogs` 同上。
- `src/services/labs.service.ts:60`：`reorderLabs` 同上。
- `supabase/migrations/001_initial_schema.sql`：`projects.title/slug`、`logs.title/date/category`、`labs.title/type` 均为 NOT NULL 且无默认值。
- `supabase/migrations/006_add_sort_order.sql`：仅 `sort_order` 有默认值。
- 对比：`gallery`、`coffee_logs` 多数列有默认值，可能不受影响。

**影响**
若线上确实报错，拖拽排序功能在项目/日志/实验室三个模块不可用；后台未统一提示错误，用户可能以为已保存。

**修复建议**
1. 改为逐条 `update({ sort_order }).eq('id', id)`（`Promise.all`），避免 upsert 插入语义。
2. 或编写数据库 RPC 批量更新排序。
3. 修复前先在测试环境构造一次拖拽保存，确认错误码。

**验证方式**
后台拖动项目顺序并刷新页面，顺序应持久化；浏览器 Network 中不应出现 23502（not_null_violation）。

### BUG-04（P1）首页项目卡片为死链且不进入详情页

**问题描述**
首页“精选项目”卡片直接将卡片链接到 `github_url`，当该字段为空时 `href` 为 `undefined`，卡片不可点击；即使有值，也会跳出站外而不是进入站内项目详情页。

**证据**
- `src/pages/Home.tsx:231`：`href={project.github_url ?? undefined}`。

**影响**
首页核心导流区块可用性差，项目详情页失去入口价值。

**修复建议**
卡片整体链接到 `/projects/${project.slug}`；GitHub 作为卡片内独立小图标，仅在 `github_url` 存在时渲染。

**验证方式**
`github_url` 为空的项目在首页可点击并进入详情；有 GitHub 的项目点击卡片进详情、点击图标跳外链。

### MAIN-01（P2）类型逃逸与 Database 类型不完整

**问题描述**
所有写操作均使用 `insert(x as never)` / `update(x as never)`，绕过了 supabase-js 的类型检查。根因是 `Database` 类型缺少 `Relationships` 字段，导致泛型推断退化。另有 `Project.timeline` 并非数据库列，却存在于 `ProjectInput` 中，存在误插入风险。

**证据**
- `src/services/*.service.ts`：`as never` 出现于 projects/logs/labs/about/contact/gallery/coffee/spaceModules/siteConfig 等。
- `src/types/database.ts:41`：`timeline?: ProjectTimelineItem[]` 属于展示数据，不是 `projects` 表字段。
- `src/types/database.ts:47`：`ProjectInput` 继承了该字段。

**影响**
字段名写错、列不存在等问题无法在编译期发现；新增字段时类型保护失效。

**修复建议**
为每张表补充 `Relationships: []`；移除 `as never` 并根据报错逐步修正类型；将 `timeline` 从 Row/Input 类型中移出，改为仅前端组装的视图类型。

**验证方式**
移除 cast 后 `npm run build` 通过；故意写错字段名应触发 TypeScript 报错。

### UX-01（P2）错误处理不统一

**问题描述**
- `gallery.service.ts` 查询失败时静默返回空数组，前台展示“暂无图片”，误导用户。
- Home、Coffee 页面没有 error 分支；Projects/About/Lab/Contact 有。
- 后台 mutation 大多没有失败提示，仅删除操作使用 `alert`；删除确认使用原生 `confirm`（共 7 处）。
- 无全局 ErrorBoundary，任何渲染异常会白屏。

**证据**
- `src/services/gallery.service.ts:15`

**影响**
故障不可见，问题定位困难；用户无法判断是“没有数据”还是“加载失败”。

**修复建议**
增加全局 ErrorBoundary；统一 `QueryState`（loading / error / empty）组件；service 不吞错；用 toast + 自定义确认弹窗替换 `alert/confirm`。

**验证方式**

### UX-02（P2）首页加载阻塞与 `featured` 未使用

**问题描述**
首页把项目、日志、首页配置、空间模块四个查询合并为一个 loading，任一查询慢都会导致整页空白。首页项目区直接取排序后的前 3 条，`featured` 字段未参与前台筛选或排序。

**证据**

**验证方式**

### PERF-01（P2）前台未分包，公开页全量挂载 AuthProvider

**问题描述**
后台页面已懒加载，但所有前台页面仍同步导入；构建产物主包 739 KB（gzip 211.68 KB），Vite 提示超过 500 KB。同时 `AuthProvider` 包裹整个应用，仅为了 Footer 的后台入口，却让所有访客初始化 Supabase Auth 并调用 `getUser()`。

**证据**
- 构建输出：`assets/index-QtJNPP76.js 738.97 kB │ gzip: 211.68 kB`
- `src/App.tsx:7-17`：前台页面全部静态导入。
- `src/App.tsx:229`：`<AuthProvider>` 位于路由最外层。
- `src/components/Footer.tsx:5`：使用 `useAuth()` 决定后台链接。

**影响**

**修复建议**
1. 前台页面改为 `lazy()` + Suspense。
2. `vite.config.ts` 增加 `manualChunks`（react / framer-motion / supabase）。
3. `AuthProvider` 移入 `/admin/*`；Footer 固定链接 `/admin/login`，由 ProtectedRoute 处理跳转。

**验证方式**
构建产物主包显著下降；公开页面 Network 中无 Supabase auth 请求。

### SEO-01（P3）页面元信息管理不完整

**问题描述**
`PageMeta` 仅渲染 title 和 description，不更新 canonical 与 og:*/twitter:*；`index.html` 中已有静态 description，会与页面内渲染的 description 同时存在；sitemap 未包含项目详情页。

**证据**
- `src/components/PageMeta.tsx:6-13`
- `index.html` 静态 `<meta name="description">` 与 og 标签

**影响**
分享卡片与搜索结果可能始终显示首页信息；重复 meta 不利于搜索引擎判断。

**修复建议**
抽 `usePageMeta` 统一 create/update title、description、canonical、og:*；移除静态 description 或仅保留兜底；构建时生成包含项目详情页的 sitemap。

**验证方式**
检查不同页面源码 head 中只有一份 description，canonical 与当前路径一致；分享预览正确。

### UI-01（P3）图片加载与上传优化

**问题描述**
列表图片没有 `loading="lazy"`、`decoding="async"` 和宽高占位，首屏可能下载全部原图；上传端允许 5 MB 原图直传，未做压缩或尺寸限制。

**证据**
- `src/pages/Gallery.tsx:70`
- `src/pages/Coffee.tsx:25`
- `src/pages/About.tsx:41`
- `src/services/gallery.service.ts:57`：`MAX_SIZE = 5MB`

**影响**
移动端流量与加载时间偏高，图片加载时布局抖动。

**修复建议**
图片加 lazy/decoding 与固定宽高比；上传前做客户端压缩或限制长边尺寸。

**验证方式**
Lighthouse 检查图片相关告警；弱网下列表不应一次性拉取全部原图。

### A11Y-01（P3）可访问性问题

**问题描述**
- `--color-text-secondary: #6b7280` 在 `#0a0a0f` 背景下对比度约 4.1:1，低于 WCAG AA 对小号文字的 4.5:1 要求。
- Gallery 图片弹窗缺少 `role="dialog"`、`aria-modal`、Esc 关闭和焦点管理。
- 移动端菜单按钮缺少 `aria-expanded`。
- 后台纯图标按钮多数只有 `title`，建议补充 `aria-label`。

**证据**
- `src/index.css:7`
- `src/pages/Gallery.tsx:94`
- `src/components/Header.tsx:49-55`
- 各后台管理页的编辑/删除图标按钮

**影响**
低视力用户可读性差；键盘用户无法正常关闭弹窗。

**修复建议**
提亮 text-secondary 或仅在正文小字改用更亮色；弹窗补齐语义与 Esc/焦点逻辑；按钮补充 aria 属性；动画支持 `prefers-reduced-motion`。

**验证方式**
用 axe/Lighthouse 检查对比度与对话框语义；Tab/Esc 可完整操作弹窗。

### MAIN-03（P3）后台路由与状态表达

**问题描述**
`AdminRoutes` 中 15 个路由重复包裹 `<ProtectedRoute>`；Gallery/Coffee 用 `editingId === 0` 表示“新建”，语义不直观且依赖 id 不会为 0 的隐含约定。

**证据**
- `src/App.tsx:82-223`
- `src/admin/pages/GalleryManage.tsx:72`、`CoffeeManage.tsx:79`

**影响**
新增后台页面时模板代码多；状态含义容易误解。

**修复建议**
使用嵌套路由 + 一个受保护布局层（`<ProtectedRoute><Outlet /></ProtectedRoute>`）；编辑状态改为 `null | 'new' | number`。

**验证方式**
未登录访问任一后台路径都跳转登录；新建/编辑流程行为不变。

### CONTENT-01（P3）硬编码内容与输入解析

**问题描述**
首页 GitHub 链接、页脚邮箱写死在组件中，而 contacts 数据已有对应字段；咖啡参数解析只识别半角冒号，中文输入法下容易解析失败。

### FUNC-01（P3）删除项目时的冗余级联

**问题描述**
删除项目前手动删除 `ai_collabs` 与 `project_timeline`，但数据库外键已配置 `ON DELETE CASCADE`，属于重复逻辑，且清理失败仅记录 warning。

**影响**

**修复建议**

**验证方式**
删除项目后其时间线与协作记录应自动消失。

### DATA-02（P3）About 页面存在无法渲染的区块键

**问题描述**
前台 `sectionLabels` 包含 `ai`，但 `renderSection` 没有 `ai` 分支。如果历史数据的 `section_order` 包含 `ai`，会渲染出“AI 协作”标题但内容为空。后台当前不提供该键，属于历史数据健壮性问题。

**证据**
- `src/pages/About.tsx:21-29`（含 `ai`）
- `src/pages/About.tsx:33-196`（无 `ai` case）
- `src/admin/pages/AboutManage.tsx:26-33`（不含 `ai`）

**影响**
仅在旧数据下出现空标题，影响轻微。

**修复建议**
删除 `ai` 键，或补充对应渲染分支；渲染前过滤掉无内容区块。

**验证方式**
构造包含 `ai` 的 `section_order` 数据，页面不应出现空标题。
