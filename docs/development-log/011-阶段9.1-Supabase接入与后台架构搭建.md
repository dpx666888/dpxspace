## 遇到的问题

1. `src/admin/hooks/useAuth.ts` 因文件扩展名为 `.ts` 但包含 JSX，导致 TypeScript 解析 JSX 时报错
2. `src/admin/components/ProtectedRoute.tsx` 中 `<br />` 被写成 HTML 实体 `&lt;br />`，造成语法错误
3. `auth.service.ts` 的 `onAuthStateChange` 两种返回结构不一致，导致调用方无法统一解构 `subscription`
4. 新 DB 类型使用 snake_case，旧的 `src/data/projects.ts` 和 `src/pages/ProjectDetail.tsx` 仍使用 camelCase，出现大量类型不匹配
5. Supabase 手写 Database 类型后，`.insert()`/`.update()` 被推断为 `never[]`，需要临时类型断言

## 解决方案

1. 将 `useAuth.ts` 重命名为 `useAuth.tsx`，并同步更新 `src/admin/README.md`
2. 将 `&lt;br />` 改回正常的 `<br />`
3. 统一 `onAuthStateChange` 返回 `{ subscription }`，Supabase 存在时返回 `supabase.auth.onAuthStateChange(...).data`
4. 重写 `src/data/projects.ts` 为 snake_case 字段、数字 id、slug 路由，并更新 Projects/ProjectDetail 页面使用 `slug` 查询
5. 在 service 写入方法中使用 `as never` 临时断言，避免阻塞阶段9.1构建；阶段9.2迁移时可替换为自动生成的 Supabase 类型
