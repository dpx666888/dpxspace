# 第 053 次开发记录 — 批次 D 滚动进度条与 Hero 视差

## 开发时间

2026-10-18

## 本次目标

增加顶部滚动进度条与首页 Hero 视差，补足滚动叙事与空间层次。执行依据：`docs/plans/阶段11-UI动效优化执行标准.md` 批次 D。

## 背景

A–C 批完成后，首屏仍有静态感；滚动过程缺少反馈。原计划使用 Framer Motion 的 `useScroll` / `useTransform` / `useSpring`。

## 修改文件

新增：

- `src/hooks/useScrollProgress.ts` — 原生滚动监听 + rAF 合并，向回调提供 `scrollY` 与全局进度
- `src/components/ScrollProgress.tsx` — 顶部 2px 渐变进度条，直接写 `scaleX`

修改：

- `src/App.tsx` — 在 `MainLayout` 中挂载进度条
- `src/pages/Home.tsx` — Hero 文字与终端分别包裹 `ParallaxLayer`；新增 `useMediaQuery`、`ParallaxInner`

删除：无

> 说明：原方案使用 `useScroll` + `useTransform`，实测 JS gzip 单批增长 **+3.59KB**，超过 3KB 限制。已暂停并获负责人确认，改用原生滚动 hook；行为与验收标准不变，体积回到 **+0.60KB**。

## 完成内容

1. 滚动进度条：固定顶部、2px、渐变、`origin-left` + `scaleX`，层级 `z-60` 高于 Header；`pointer-events-none` 不拦截点击。
2. 原生滚动 hook：`scroll`/`resize` 事件配合 rAF 合并，滚动期间不触发 React 重渲染；卸载时移除监听并取消未执行帧。
3. Hero 视差：文字区随滚动上移并淡出（0→-40px，透明度 1→0.35）；终端反向位移（0→+40px，不淡出），形成纵深。
4. 视差仅在 `min-width: 768px` 且非 reduced-motion 时挂载；否则不注册滚动监听，DOM 中不存在视差层。
5. 进度条按 `scrollY / (scrollHeight - innerHeight)` 计算，滚动到底为 1。

## 遇到的问题

1. 使用 Framer Motion 滚动工具导致 JS gzip 单批 +3.59KB，超出 3KB 限制；累计 218.41KB 虽未超 219KB，但剩余空间不足 1KB。
2. 去掉 `useSpring` 仅回收约 0.4KB，仍不达标。

## 解决方案

1. 按暂停流程向负责人说明并给出方案；负责人选择“改原生滚动 hook”。
2. 新增 `useScrollProgress`，移除 `useScroll`/`useTransform`/`useSpring`；最终 JS gzip +0.60KB、CSS +100B，均回到限制内。
