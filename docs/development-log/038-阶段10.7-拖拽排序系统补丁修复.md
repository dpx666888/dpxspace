# 阶段10.7-拖拽排序系统补丁修复记录

**日期**：2026-07-30
**类型**：Bug 修复
**关联**：阶段10.7-dpxspace-CMS体验问题修复指导方案

---

## 问题诊断

项目/实验室/成长日志三个管理页面的拖拽排序功能完全失效，无法通过拖拽修改卡片位置。

### 根因分析

经过与协作记录页（拖拽正常）逐行对比，定位到两个关键差异：

| 对比项 | 协作记录（正常） | 项目/实验室/日志（异常） |
|---|---|---|
| 编辑按钮元素 | `<button onClick>` | `<Link to>` → 渲染为 `<a>` 标签 |
| `onDragStart` | 无 `setData` | 无 `setData` |

**根因 1（主因）**：`<Link>` 渲染为 `<a>` 标签，浏览器对 `<a>` 标签有原生拖拽行为（拖拽链接到收藏夹/创建快捷方式）。当 `<a>` 标签作为 `draggable` 父元素的子节点时，浏览器会优先触发 `<a>` 的原生拖拽，导致父元素的自定义 `dragstart` 事件不被触发，整个拖拽链路中断。

**根因 2（次因）**：`onDragStart` 中未调用 `e.dataTransfer.setData()`。Firefox 规范要求必须在 `dragstart` 中设置 drag data 才会启动拖拽操作。

### 附带修复

`getProjects()` 服务函数中存在 `.eq('status', 'published')` 过滤，导致后台管理列表不显示草稿状态的项目。

---

## 修改清单

### 1. `src/admin/pages/ProjectsManage.tsx`

| 变更 | 说明 |
|---|---|
| `import { Link }` → `import { Link, useNavigate }` | 引入 `useNavigate` |
| 新增 `const navigate = useNavigate()` | 用于编程式导航 |
| `onDragStart={() => {...}}` → `onDragStart={(e) => { e.dataTransfer.setData('text/plain', ''); ... }}` | 兼容 Firefox 拖拽 |
| `<Link to={.../edit}>` → `<button onClick={() => navigate(.../edit)}>` | 消除 `<a>` 标签拖拽冲突 |

### 2. `src/admin/pages/LabsManage.tsx`

同上四项变更。

### 3. `src/admin/pages/LogsManage.tsx`

同上四项变更。

### 4. `src/services/projects.service.ts`

移除 `getProjects()` 中 `.eq('status', 'published')` 过滤条件，后台管理列表恢复显示所有状态的项目。

## 影响范围

- **受影响页面**：后台项目管理、实验室管理、成长日志管理
- **兼容性修复**：Firefox 浏览器拖拽支持
- **功能恢复**：草稿状态项目在后台管理列表可见
- **非破坏性**：前台首页 `getProjects()` 共用同一函数，但首页通过 `useProjects` hook 的 `select` 排序展示，不受影响
