## 二、快速开始

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（复制 .env.example → .env.local）
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-anon-key>

# 3. 初始化数据库：在 Supabase SQL Editor 按编号顺序执行
#    supabase/migrations/001_initial_schema.sql → 011_ai_project_link.sql

# 4. 手动创建 Storage bucket
#    Supabase Dashboard → Storage → 新建 bucket "gallery"（Public）
#    再执行 010_storage_fix.sql 配置上传/删除/读取策略

# 5. 启动
npm run dev      # 开发
npm run build    # 生产构建（tsc -b && vite build）
```

> 未配置 Supabase 时，网站以前端静态数据（`fallbackData.ts`）运行，后台不可用——这是刻意的降级设计，便于纯前端演示。

## 四、工程亮点（含"为什么"）

1. **优雅降级** — Service 层检测 Supabase 未配置时回退静态数据。*为什么*：让前端可脱离后端独立演示，也让新协作者 clone 后不配数据库就能跑起来。
2. **环境感知 logger** — `logger.warn/error` 用 `import.meta.env.DEV` 门控。*为什么*：生产环境静默 35+ 处 console 调用，避免泄露内部状态、污染控制台。
3. **级联删除** — 删除项目时同步清理 `ai_collabs`、`project_timeline`。*为什么*：避免孤儿数据累积，PostgreSQL 外键未设 CASCADE 时在应用层兜底。
4. **图片上传前置校验** — 类型白名单 + 5MB 上限 + 文件名净化（去除特殊字符）。*为什么*：在成本最低的客户端拦截，避免无效请求打到 Storage、避免非法文件名注入。
5. **前后台共用数据层** — 同一 `useProjects`/`getProjects` 服务前后台。*为什么*：单一数据源，后台改完前台自动一致，杜绝双份逻辑漂移。
6. **HTML5 原生拖拽**（放弃 dnd-kit）— 用 `useRef` + 手动事件编排。*为什么*：为一个排序功能引入 30KB+ 依赖不划算，原生 API 足够。

## 七、已知问题与改进清单

### 🔴 P0 — 安全（最紧急）

**RLS 策略盲区**：所有表的写策略是 `auth.uid() IS NOT NULL`，意味**任何已认证用户都能写全部表**。若 Supabase Auth 未关闭注册，任何人注册账号即可改你的项目、删你的日志。

**修复**：Supabase Dashboard → Authentication → 关闭 "Allow new users to sign up"；或把策略收紧为 `auth.uid() = '<你的 user id>'`。

### 🟠 P1 — 内容完成度（比代码优化更紧急）

网站上线了，但 Hero 简介、项目故事、关于我仍大量占位符。**作为电子名片，它现在还没完成名片的核心功能。**

优先补：① 首页一句话定位 ② 关于我 3 段简介 ③ 至少 2 个项目的完整故事。代码可以慢慢优化，内容是名片存在的前提。

### 🟠 P1 — 性能

Bundle **921KB**（index.js），主因 React Query + Framer Motion + lucide-react 全量引入。低成本优化：

- **路由级 `React.lazy()` 分包** — 后台代码访客根本不该加载，收益最大
- **Framer Motion 改 `LazyMotion + domAnimation`** — 可砍 30KB+

### 🟡 P2 — SEO

已有基础 meta，但缺：

- `sitemap.xml` + `robots.txt`（静态放 `public/`）
- **JSON-LD Person 结构化数据**（让 Google 认识"丁鹏翔"实体）
- 每页独立 title/description（用 React 19 原生 `<title>`）
- `og:image`（现为空，分享无预览图）
- ⚠️ 现有 `og:url` 指向 `github.com/dpx666888`，**应改为站点域名**（当前是错的）

### 🟡 P2 — 代码整洁

| 项 | 处理方式 |
|---|---|
| **死代码** | `data/projects.ts`、`profile.ts`、`logs.ts`、`lab.ts`、`aiCollabs.ts`（~273 行）。已确认仅 `fallbackData.ts` 被引用。**先用 `npx knip` 扫描**，再看 `git blame` 确认无回滚需求再删 |
